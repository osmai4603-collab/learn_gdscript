### 1. المقدمة ونطاق البحث

تعتبر معالجات اللغات البرمجية (**Language Processors**) الركيزة الأساسية لعلوم الحاسوب وهندسة البرمجيات. يهدف هذا البحث إلى توثيق المواصفات الهندسية، المعمارية، والمعايير القياسية التي تحكم تصميم وبناء **المترجمات (Compilers)** و**المفسرات (Interpreters)** بالاستناد إلى:

- المواصفات والمعاجم القياسية لمنظمات المعايير الدولية (**ISO**, **IEC**, **IEEE**).
- المناهج التأسيسية لجمعيات الحوسبة الأكاديمية (**ACM / IEEE Computer Science Curricula**).
- المؤلفات الكلاسيكية والمرجعية العالمية المعتمدة في كبرى الجامعات ومختبرات البحث.
- المعماريات الصناعية الحديثة (مثل **LLVM**, **GCC**, **JVM**, و **GDScript VM** في محرك Godot).

### 3. التعريفات المعيارية والتمايز الجوهري (Compiler vs Interpreter)

وفقاً للمعيارين **ISO/IEC 2382-7** و **IEEE 24765**:

```text
+----------------------------------------------------------------------------------------------------+
|                                    Language Processor Taxonomy                                     |
+----------------------------------------------------------------------------------------------------+
|                                                                                                    |
|  [Source Code]                                                                                     |
|        |                                                                                           |
|        +-----------------------------------+-----------------------------------+                   |
|        |                                   |                                   |                   |
|        v (Ahead-Of-Time)                   v (Hybrid / Bytecode VM)            v (Direct Execution)|
|  +---------------+                   +---------------+                   +---------------+         |
|  |   COMPILER    |                   |   COMPILER    |                   |  TREE-WALKING  |         |
|  |  (Pure AOT)   |                   |  (Front-End)  |                   |  INTERPRETER  |         |
|  +---------------+                   +---------------+                   +---------------+         |
|        |                                   |                                   |                   |
|        v                                   v                                   v                   |
|  [Machine Code /                  [Intermediate Bytecode]                 Direct AST               |
|   Native Binary]                           |                             Evaluation Results        |
|        |                             +-----+-----+                                                 |
|        v                             |           |                                                 |
|   Direct CPU                         v           v                                                 |
|    Execution                   +-----------+ +-----------+                                         |
|                                | VM Interp | |  JIT VM   |                                         |
|                                +-----------+ +-----------+                                         |
|                                      |             |                                               |
|                                      v             v                                               |
|                                   Runtime      Native Code                                         |
|                                  Execution     Execution                                           |
+----------------------------------------------------------------------------------------------------+
```

#### أ. المترجم (Compiler)

- **التعريف المعياري (ISO/IEC 2382-7):** برنامج حاسوبي يترجم برنامجاً مكتوباً بلغة عالية المستوى (لغة المصدر Source Language) إلى برنامج مكافئ مكتوب بلغة أخرى (اللغة الهدف Target Language - عادة كود آلة، لغة تجميع، أو كود وسيط) دون تنفيذ البرنامج المصدري أثناء عملية الترجمة.

- **الخصائص الجوهرية:**
  - الترجمة تتم مسبقاً (Ahead-Of-Time - AOT).
  - فصل تام بين زمن الترجمة (Compile-Time) وزمن التشغيل (Runtime).
  - توليد مخرجات مادية مستقلة (ملف تنفيذي Standalone Executable، مكتبة ثنائية Shared Library، أو ملف كود وسيط Bytecode).

#### ب. المفسر (Interpreter)

- **التعريف المعياري (ISO/IEC 2382-7):** برنامج حاسوبي يترجم وينفذ كل تعليمة في برنامج لغة عالية المستوى بالتتابع خطوة بخطوة أثناء وقت التشغيل، دون إنتاج برنامج تنفيذي كامل مسبقاً.

- **الخصائص الجوهرية:**
  - الترجمة والتنفيذ متزامنان أثناء وقت التشغيل.
  - لا يوجد ملف تنفيذي منفصل؛ وجود المفسر وبيئة تشغيله إلزامي لتشغيل الكود.
  - استجابة فورية (Low Startup Latency)، مما يجعله مثالياً للبرمجة النصية والتطوير التفاعلي (REPL).

#### ج. الأنظمة الهجينة ومترجمات وقت التشغيل (Hybrid & JIT Compilers)

- **النموذج الهجين (Two-Phase Execution):** يترجم الكود المصدري أولاً عبر مترجم خفيف إلى لغة وسيطة منخفضة المستوى تُعرف بـ **البايت كود (Bytecode)**، ثم يتم تشغيل البايت كود عبر آلة افتراضية مفسرة (**Virtual Machine Interpreter**) كما في **Python (CPython)** و **GDScript 4**.

- **الترجمة أثناء التشغيل (Just-In-Time - JIT):** تقوم الآلة الافتراضية بمراقبة البايت كود، وتحويل الأجزاء كثيفة الاستخدام (Hot Spots / Loops) أثناء وقت التشغيل مباشرة إلى كود آلة حقيقي (Native Machine Code) لتحقيق سرعات تقارب اللغات المترجمة (مثل V8 في JavaScript و PyPy و HotSpot JVM).

### 4. معمارية الواجهة الأمامية المشتركة (The Front-End Pipeline)

تتطابق المترجمات والمفسرات في معمارية الواجهة الأمامية (**Front-End**)؛ حيث تتولى تحويل الكود المكتوب كنص عادي إلى بنية بيانات مهيكلة غنية بالمعلومات الدلالية:

```text
[كود المصدر النصي] 
       │
       ▼
[التحليل المعجمي (Lexer / Scanner)] ───► سيل الرموز الدلالية (Tokens)
       │
       ▼
[التحليل النحوي (Parser)]           ───► شجرة الإعراب المجردة (AST)
       │
       ▼
[التحليل الدلالي (Type Checker)]     ───► شجرة AST الموثقة + جدول الرموز (Decorated AST + Symbol Table)
```

#### أ. التحليل المعجمي (Lexical Analysis / Scanner)

- **المسؤولية:** تحويل سيل المحارف (Stream of Characters) إلى سيل من الوحدات المعجمية الدلالية (**Tokens**).

- **المواصفات القياسية:**
  1. **النمذجة الرياضية:** بناء التعابير المنتظمة (**Regular Expressions**) ومطابقتها باستخدام آلات الحالة المحدودة القطعية (**DFA**) أو غير القطعية (**NFA**).
  2. **التصنيف المعياري للرموز:**
     - الكلمات المحجوزة (`Keywords` مثل `func`, `class`, `var`, `if`).
     - المعرفات (`Identifiers` لأسماء المتغيرات والدوال).
     - المعاملات (`Operators` الرياضية والمنطقية والبتية).
     - القيم الحرفية الثابتة (`Literals`: أرقام، نصوص، قيم بوليانية).
  3. **تتبع الإحداثيات المكانية (Source Location Tracking):**
     - حفظ مسار الملف، رقم السطر، رقم العمود، وموقع الإزاحة البايتية (`Byte Offset`) لكل رمز؛ لتمكين دقة التشخيص وإبراز الأخطاء في المحررات.
  4. **إدارة المسافات والحواشي:**
     - معالجة المسافات البيضاء والتعليقات، والتعامل مع اللغات المعتمدة على المحاذاة (Off-side Rule / Indentation-sensitive) مثل Python و GDScript عبر إصدار رموز خاصة (`INDENT` و `DEDENT`).

#### ب. التحليل النحوي (Syntactic Analysis / Parser)

- **المسؤولية:** التحقق من مطابقة سيل الرموز لقواعد بناء الجملة (Grammar) وبناء شجرة النحو المجردة (**AST - Abstract Syntax Tree**).

- **المواصفات القياسية:**
  1. **التوصيف بالقواعد خالية السياق (Context-Free Grammar - CFG):** التعبير عن صياغة اللغة باستخدام صيغة باكس-ناور المعيارية (**BNF / EBNF**).
  2. **خوارزميات الإعراب المعتمدة:**
     - **من أعلى لأسفل (Top-Down):**
       - *الانحدار التعاودي (Recursive Descent Parsing)*: الخوارزمية الأكثر انتشاراً في اللغات الحديثة لقابليتها العالية للتخصيص وجودة رسائل الخطأ.
       - *إعراب برات (Pratt Parsing / Top-Down Operator Precedence)*: المعيار الصناعي المفضل لإعراب التعبيرات الرياضية والعمليات المعقدة بناءً على مستويات الأسبقية (Precedence) والارتباطية (Associativity).
       - *LL(k) Parsers*: تفحص الرموز من اليسار إلى اليمين مع استشراف $k$ من الرموز.
     - **من أسفل لأعلى (Bottom-Up):**
       - *LR(k) و LALR(1)*: تُستخدم غالباً في مولدات الإعراب الآلية (مثل Yacc و Bison).
  3. **بنية شجرة النحو المجردة (Abstract Syntax Tree):**
     - تمثيل بنيوي هرمي يتجاهل التفاصيل النحوية الزائدة (مثل الأقواس والفواصل المنقوطة) ويركز على المعنى الهيكلي للتعليمات والتعبيرات البرمجية.
  4. **مرونة التعافي من الأخطاء (Error Recovery & Resilience):**
     - مواصفة حرجة جداً للمحررات وأدوات الـ Language Server (LSP)؛ حيث يجب ألا يتوقف المحلل عند أول خطأ نحوي، بل يطبق استراتيجيات مثل:
       - *نمط الذعر (Panic Mode Recovery)*: القفز إلى الرمز المتزامن التالي (Synchronizing Token مثل `;` أو سطر جديد أو كلمة مفتاحية).
       - *عقد الخطأ المؤقتة (Error / Synthetic Nodes)*: استبدال الرمز المفقود بعقدة افتراضية للسماح بمواصلة إعراب بقية المستند وتقديم إكمال تلقائي كامل.

#### ج. التحليل الدلالي (Semantic Analysis)

- **المسؤولية:** التحقق من سلامة المنطق الداخلي للبرنامج، معاني العمليات، وتطبيق القيود التي تعجز القواعد النحوية الصرفة عن ضبطها.

- **المواصفات القياسية:**
  1. **جدول الرموز المتداخل (Hierarchical / Scoped Symbol Table):**
     - بنية بيانات شجرية تتبع النطاقات (Global, Class, Function, Block scopes).
     - تسجيل كينونة كل متغير (اسم، نوع، مكان التصريح، إمكانية التعديل `const/var`).
     - حل المعرفات الدلالي (**Name Binding & Resolution**).
  2. **نظام فحص الأنواع (Type System & Type Checking):**
     - التحقق من توافق الأنواع في العمليات (مثل منع جمع نص مع مصفوفة بدون تحويل).
     - استنتاج الأنواع التلقائي (**Type Inference**).
     - التمييز بين الأنواع الصارمة في وقت الترجمة (Static Typing) والأنواع الديناميكية (Dynamic Typing / Variants).
  3. **التحقق من سلامة التدفق والقيود المتقدمة (Control-Flow & Semantic Checks):**
     - كشف استخدام المتغيرات غير المعرفة أو غير المهيأة (Definite Assignment).
     - فحص مسارات الإرجاع (ضمان أن جميع مسارات الدالة تعيد قيمة إذا لزم الأمر).
     - التحقق من سلامة استخدام أوامر التحكم (`break` و `continue` داخل الحلقات فقط).

### 5. المواصفات المعمارية الخاصة بالمترجمات (Compiler Middle-End & Back-End)

في المترجمات الكاملة، يُفصل الواجهة الأمامية عن الواجهة الخلفية عبر طبقة وسيطة (**Middle-End**) وطبقة توليد الأكواد (**Back-End**):

```text
[Front-End AST]
       │
       ▼
[توليد التمثيل الوسيط (IR Generation)]  ───► كود IR (مثل LLVM IR أو SSA)
       │
       ▼
[محرك التحسين (Optimization Engine)]    ───► IR محسن ومختصر
       │
       ▼
[الواجهة الخلفية (Target Code Gen)]
       ├─► اختيار التعليمات (Instruction Selection)
       ├─► تخصيص السجلات (Register Allocation)
       └─► جدولة الأوامر (Instruction Scheduling)
       │
       ▼
[الكود المستهدف: Binary / Machine Code]
```

#### أ. التمثيل الوسيط (Intermediate Representation - IR)

- **المواصفات:**
  - لغة وسيطة مستقلة تماماً عن لغة المصدر وعن معمارية العتاد المستهدف (Hardware Architecture).
  - **شكل التعيين الأحادي الساكن (Static Single Assignment - SSA Form):** المعيار القياسي الدولي للمترجمات الحديثة (مثل LLVM و GCC)؛ حيث يتم إسناد القيمة لكل متغير مرة واحدة فقط، مما يجعل تتبع تدفق البيانات وتحسين المتغيرات ذا كفاءة حسابية فائقة.

#### ب. محرك التحسين (Optimization Engine)

- **المواصفات والتحسينات المعيارية:**
  - **طي الثوابت ونشرها (Constant Folding & Propagation):** حساب التعبيرات الثابتة أثناء وقت الترجمة (مثل استبدال `2 + 3` بـ `5`).
  - **إزالة الأكواد الميتة (Dead Code Elimination):** حذف الدوال أو العبارات البرمجية التي يستحيل الوصول إليها أو لا تؤثر مخرجاتها على النتيجة.
  - **تضمين الدوال (Function Inlining):** استبدال استدعاء الدوال الصغيرة بجسم الدالة مباشرة لتوفير عبء القفز وتخصيص إطار المكدس.
  - **تحسين الحلقات التكرارية (Loop Optimizations):** إخراج العمليات غير المتغيرة خارج الحلقة (Loop-Invariant Code Motion)، وفك الحلقات (Loop Unrolling).

#### ج. توليد الكود المستهدف (Code Generation)

- **المواصفات الهندسية للواجهة الخلفية:**
  1. **اختيار التعليمات (Instruction Selection):** ترجمة عمليات الـ IR إلى تعليمات المعالج المستهدف (x86-64, ARM64, RISC-V).
  2. **تخصيص السجلات (Register Allocation):** حل معضلة تعيين عدد لانهائي من متغيرات الـ IR إلى عدد محدود جداً من سجلات المعالج المادية، باستخدام خوارزميات مثل:
     - *تلوين الرسوم البيانية (Graph Coloring)*: الخوارزمية الأدق لأفضل استغلال للسجلات.
     - *المسح الخطي (Linear Scan)*: أسرع في وقت الترجمة (شائعة في مترجمات JIT).
  3. **جدولة التعليمات (Instruction Scheduling):** إعادة ترتيب التعليمات لتفادي التوقفات التزامنية في خطوط أنابيب المعالج (CPU Pipeline Hazards).

### 6. المواصفات المعمارية الخاصة بالمفسرات (Interpreter & Virtual Machine Runtime)

تتميز المفسرات بتركيز معظم تعقيدها الهندسي داخل **بيئة وقت التشغيل (Runtime Environment)** بدلاً من طبقة توليد كود الآلة:

#### أ. نماذج التقييم: المفسر الشجري مقابل آلة البايت كود

| وجه المقارنة | المفسر الشجري (Tree-Walking Interpreter) | مفسر آلة البايت كود (Bytecode VM Interpreter) |
| :--- | :--- | :--- |
| **آلية التنفيذ** | يجوب شجرة الـ AST تعاودياً وينفذ العقد في الحال. | يترجم الـ AST إلى مصفوفة بايتات مدمجة تُنفذ تتابعياً. |
| **سرعة البدء (Startup)** | فورية جداً (لا توجد مرحلة وسيطة). | تأخير طفيف لتوليد الـ Bytecode. |
| **سرعة التنفيذ (Throughput)** | بطيئة نسبياً (عبء استدعاء الدوال وشتات الذاكرة Cache Misses). | سريعة ومتقاربة في الذاكرة (High Cache Locality). |
| **استهلاك الذاكرة** | مرتفع (الاحتفاظ بالشجرة الكاملة في الذاكرة). | منخفض جداً (مصفوفة بايتات مضغوطة). |
| **أمثلة شهيرة** | النماذج التعليمية الأولية، لغة Bash/Shell. | **GDScript (Godot 4)**، CPython، Lua، JVM. |

#### ب. معماريات الآلات الافتراضية: المكدس (Stack-Based) مقابل السجلات (Register-Based)

وفقاً للمراجع الأكاديمية وهندسة الآلات الافتراضية:

```text
+------------------------------------+------------------------------------+
|  Stack-Based VM (مثل JVM / CPython) |  Register-Based VM (مثل Lua 5 / Dalvik)|
+------------------------------------+------------------------------------+
|  العملية: جمع متغيرين (x = a + b)     |  العملية: جمع متغيرين (x = a + b)     |
|                                    |                                    |
|  LOAD a       ; دفع a للمكدس         |  ADD R1, R2, R3 ; جمع R2+R3 إلى R1 |
|  LOAD b       ; دفع b للمكدس         |                                    |
|  ADD          ; سحب القيمتين وجمعهما|  (تعليمة واحدة مباشرة)              |
|  STORE x      ; حفظ النتيجة في x    |                                    |
|                                    |                                    |
|  عدد التعليمات: كبير               |  عدد التعليمات: قليل                |
|  حجم التعليمة: صغير وبسيط (1 بايت) |  حجم التعليمة: أكبر (تتضمن أرقام   |
|  بناء المترجم: في غاية السهولة      |                 السجلات الافتراضية) |
|                                    |  كفاءة التنفيذ: أسرع لقلة دورات     |
|                                    |                 حلقة التوزيع       |
+------------------------------------+------------------------------------+
```

#### ج. حلقة التوزيع والتنفيذ (Instruction Dispatch Loop)

- **المسؤولية:** المحرك التكراري المركزي للمفسر الذي يقوم بجلب التعليمة التالية، فك تشفيرها، وتنفيذها:
  1. **Switch-Based Dispatch:** الأسلوب الأبسط؛ حلقة `while` تفحص `opcode` عبر عبارة `switch`. يعيبه تكلفة القفز العشوائي في خط أنابيب المعالج (Branch Misprediction).
  2. **Direct Call Threading / Token Threading:** مصفوفة من مؤشرات الدوال (Function Pointers) تقفز مباشرة إلى دالة التعليمة بدون `switch`.
  3. **Direct Threaded Code (عبر مؤشرات التسميات Labels as Values):** الأسلوب الأكثر كفاءة عالمياً؛ حيث تنتهي كل تعليمة بالقفز المباشر (`goto *dispatch_table[opcode]`) للتعليمة التالية، مما يقلل هدر المعالج إلى أدنى حد ممكن (كما في مفسرات CPython و Lua المكتوبة بلغة C).

#### د. النظام البيئي لوقت التشغيل (Runtime Subsystems)

- **إدارة مكدس الاستدعاءات (Call Stack & Activation Frames):**
  - تخزين إطارات الدوال المستدعاة، المتغيرات المحلية، ومؤشر العودة (**Instruction Pointer / Program Counter**).

- **إدارة الذاكرة الديناميكية والكنس (Heap Management & Garbage Collection):**
  - **عد المراجع (Reference Counting):** تحرير الكائنات فور وصول عداد مؤشراتها للصفر (تستخدمه GDScript و Swift و CPython)، مع الحاجة لآلية فحص الحلقات المغلقة (Cycle Detector).
  - **الكنس بالتتبع (Tracing Garbage Collection):** خوارزميات مثل *Mark-and-Sweep* أو *Generational GC* التي تجوب الكائنات دورياً من الجذور (Roots) لتحرير غير الموصول منها.
- **واجهة استدعاء الدوال الأجنبية (Foreign Function Interface - FFI):**
  - تمكين لغة البرمجة المفسرة من استدعاء مكتبات C/C++ وواجهات نظام التشغيل المباشرة.

### 7. المعايير القياسية العالمية للجودة والاعتمادية (Non-Functional Requirements)

تحدد المعايير الدولية لهندسة النظم البرمجية (**ISO/IEC 25010**) متطلبات الجودة الصارمة للمترجمات والمفسرات:

| المعيار الهندسي | الوصف والمتطلبات القياسية الدولية |
| :--- | :--- |
| **الحفاظ الدلالي (Semantic Preservation)** | المطلب الأهم وفق كتب المترجمات؛ يجب أن يُطابق سلوك البرنامج بعد الترجمة دلالات لغة المصدر المحددة في المواصفة الرسمية بنسبة 100% دون أي سلوك جانبي غير متوقع. |
| **سلامة وموثوقية التشخيص (Diagnostics Quality)** | إنتاج رسائل خطأ واضحة وتوصيفية تتضمن: سياق الخطأ، رقم السطر، رقم العمود، تلوين النص، وتلميحات إرشادية لاقتراح الحلول المناسبة، مع الامتناع المطلق عن انهيار المترجم (No Compiler Crashes/Panics). |
| **الحتمية والتكرارية (Reproducible Builds & Determinism)** | يجب أن يؤدي إدخال نفس الكود المصدري مع نفس المتغيرات إلى إنتاج نفس المخرجات الثنائية تماماً بايت تلو الآخر، دون التأثر بالتوقيت أو ترتيب نظام الملفات. |
| **الكفاءة الزمنية والمكانية (Time & Space Complexity)** | ألا تتجاوز مرحلة التحليل النحوي والمعجمي التعقيد الزمني الخطي $O(N)$ بالنسبة لحجم الكود المصدري، مع كبح استهلاك الذاكرة في حدود دنيا. |
| **عزل وقت التشغيل والأمان (Sandboxing & Safety)** | للمفسرات: التحقق من حدود المصفوفات (Bounds Checking)، منع طفحان الذاكرة (Buffer Overflows)، وتوفير بيئة تنفيذ معزولة إذا كانت اللغة مخصصة لبيئات مضمنة (Embedded Scripting). |

### 8. التطبيقات العملية لمهندسي اللغات ومطوري أدوات المحررات (Editor & Tooling Insights)

إذا كنت تبني **محرراً برمجياً (Editor)**، **محللاً للغة (LSP Server)**، أو **بيئة تشغيل خاصة** (مثل لغة GDScript أو غيرها):

1. **التحليل النحوي المتسامح مع الأخطاء (Fault-Tolerant / Resilient AST):**
   - المترجمات التقليدية تتوقف أو تتخطى الأجزاء الخاطئة؛ بينما **محلل المحرر البرمجي** يجب أن يبني شجرة AST كاملة حتى لو كان الكود غير مكتمل أو يحتوي أخطاءً نحوية (Syntax Incomplete)، لأن المبرمج يكتب باستمرار أكواداً مؤقتة وغير صالحة نحويًا ويحتاج إلى دعم المحرر في تلك اللحظة بالذات.
2. **بروتوكول خادم اللغة المعياري (Language Server Protocol - LSP):**
   - بدلاً من دمج المحلل بالكامل في واجهة المستخدم، يتم فصل:
     - **الواجهة الأمامية (Lexer + Parser + Type Checker)** لتعمل كخدمة خلفية (LSP Server).
     - التواصل مع واجهة المحرر عبر JSON-RPC لتقديم: الإكمال التلقائي (Auto-completion)، الوثائق السريعة (Hover Info)، الانتقال للتعريف (Go to Definition)، وإعادة التسمية (Refactoring).
3. **التلوين الصياغي المتعدد (Two-Tier Highlighting):**
   - **المستوى الأول (Fast Regex / Lexer-based):** تلوين فوري سريع جداً أثناء الكتابة (الكلمات المفتاحية، النصوص، التعليقات).
   - **المستوى الثاني (Semantic Highlighting):** بعد انتهاء التحليل الدلالي، يتم تحديث التلوين لتمييز أسماء الأصناف والدوال والمعرفات المحلية عن العامة بدقة تامة.

### خلاصة واستنتاج

إن بناء أي مفسر أو مترجم احترافي لا ينطلق من آليات عشوائية، بل يستند إلى خط إنتاج هندسي موثق عالمياً:

1. **واجهة أمامية** صارمة لتحليل المعجم، النحو، والدلالة بالاعتماد على نظريات الحوسبة الآلية والقواعد خالية السياق.
2. **واجهة وسيطة وخلفية** تركز إما على تحسين الكود وتوليد كود العتاد (المترجم)، أو إدارة آلة افتراضية سريعة بذاكرة نظيفة ومحكمة (المفسر).
3. **تطبيق معايير الاعتمادية ISO/IEEE** في التشخيص، وتسامح الأخطاء، وحفظ المعنى الدلالي لضمان تجربة برمجية متينة ومستقرة.
