# التصور المرئي للتطبيق عند تنفيذ الأولوية الأولى

## الهدف من هذا التصور

يشرح هذا الملف كيف يمكن أن يبدو التطبيق إذا نُفذت ميزات **الأولوية الأولى** من [وثيقة أفكار تطوير تجربة تعلّم GDScript](./product_ideas_for_learning_gdscript.md): مسار دروس متدرج، محرر لتجربة الشيفرة، تمارين، تلميحات وتغذية راجعة، وحفظ محلي للتقدم.

هذا **تصور واجهة وتجربة استخدام** وليس تصميماً نهائياً أو وصفاً لواجهة موجودة حالياً. التطبيق ما زال يحتاج إلى تنفيذ الشاشات فعلياً. الفكرة أن تبدو الواجهة بسيطة ومشجعة، وأن يكون الإجراء الأهم واضحاً: **ابدأ الدرس أو تابع من حيث توقفت**.

## الانطباع العام

- التطبيق باللغة العربية واتجاه تنقّل الواجهة RTL.
- نصوص GDScript في المحرر والأمثلة تبقى LTR، حتى لا تختلط الأقواس وعلامات الترقيم مع العربية.
- استخدام ألوان هادئة ومساحات فارغة كافية، مع لون تمييز واحد للأزرار والإجراءات الأساسية.
- لكل درس عنوان وهدف واضحان، مع تجنب حشد المرجع النظري في الشاشة الرئيسية.
- لا يحتاج المستخدم إلى إنشاء حساب كي يبدأ؛ يحفظ التطبيق تقدمه على الجهاز.
- لا تعرض الواجهة لعباً أو مشاهد Godot فعلية إلا إذا كان ذلك مدعوماً؛ يمكن توضيح أن ناتج المرحلة الأولى هو تنفيذ الشيفرة أو مخرجاتها النصية.

## بنية التطبيق الأساسية

يمكن أن تتكون النسخة الأولى من أربع وجهات رئيسية:

1. **الرئيسية:** استئناف التعلم، عرض الدرس التالي والتقدم العام.
2. **المسار:** وحدات اللغة والدروس وحالاتها (مكتمل، حالي، قادم).
3. **المشاريع:** مشروع تطبيقي بسيط يفتح بعد التقدم في الأساسيات، أو يعرض بطاقة «قريباً» في البداية.
4. **الإعدادات:** حجم الخط، المظهر، المساعدة، ومسح التقدم المحلي.

على الهاتف، يظهر تنقل سفلي ثابت بهذه الوجهات. على الشاشات الأوسع يمكن تحويله إلى شريط جانبي أو إبقاؤه في شريط علوي؛ لا ينبغي تغيير ترتيب المحتوى أو إخفاء زر متابعة الدرس.

## قالب الشاشة الرئيسية

### مخطط للهاتف

```text
┌──────────────────────────────────────┐
│ تعلّم GDScript                [⚙]    │
├──────────────────────────────────────┤
│ أهلاً بك!                             │
│ لنحوّل فكرة لعبتك إلى شيفرة.          │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ مسارك التعليمي                    │ │
│ │ ███████░░░░░░░░  3 من 10 دروس    │ │
│ │                                  │ │
│ │ الدرس التالي                      │ │
│ │ الشروط: اجعل البرنامج يختار       │ │
│ │ حسب الحالة                        │ │
│ │ حوالي 5 دقائق                     │ │
│ │ [ تابع التعلّم ← ]                │ │
│ └──────────────────────────────────┘ │
│                                      │
│ ┌──────────────────────────────────┐ │
│ │ جرّب الآن                         │ │
│ │ غيّر قيمة المتغير وشاهد الناتج.   │ │
│ │ [ افتح تجربة قصيرة ]              │ │
│ └──────────────────────────────────┘ │
│                                      │
│ وحدات المسار                         │
│ [١ أساسيات] [٢ الشروط] [٣ الحلقات]   │
│ [عرض كل الدروس ←]                   │
│                                      │
│ الرئيسية    المسار    المشاريع   ⚙   │
└──────────────────────────────────────┘
```

هذا مخطط هيكلي، وليس اقتراحاً حرفياً للأيقونات أو الألوان. في الهاتف، تُرتب العناصر عمودياً وتكون بطاقة متابعة الدرس أول عنصر عملي بعد الترحيب.

### مكونات الشاشة الرئيسية

#### 1. الشريط العلوي

- اسم التطبيق أو شعاره النصي: **تعلّم GDScript**.
- زر إعدادات صغير وسهل الوصول.
- يمكن أن يظهر زر المساعدة هنا أو داخل قائمة الإعدادات، لكن لا تُضاف إشعارات أو عناصر زخرفية تنافس زر متابعة الدرس.

#### 2. الترحيب والهدف

للمستخدم الجديد:

> أهلاً بك! تعلّم GDScript خطوة بخطوة، واكتب أول برنامج لك.

للمستخدم العائد:

> أهلاً بعودتك! درس قصير جديد بانتظارك.

يمكن عرض هدفه (مثل صنع لعبة) إن اختاره. لا يلزم إدخال الاسم أو تسجيل الدخول.

#### 3. بطاقة «تابع التعلّم»

هي العنصر الأبرز في الصفحة، وتحتوي على:

- اسم الوحدة والدرس الحالي أو التالي.
- سطر يشرح ما سيتعلمه المستخدم.
- تقدير زمني تقريبي مثل «5 دقائق».
- مؤشر تقدم مفهوم، مع إرفاقه بنص مثل «3 من 10 دروس» حتى لا يعتمد على اللون وحده.
- زر أساسي واحد: **ابدأ الدرس** للمستخدم الجديد أو **تابع التعلّم** للمستخدم العائد.

عند فتح التطبيق لأول مرة، توجه البطاقة إلى الدرس الأول بدلاً من عرض تقدم فارغ أو شاشة تسجيل.

#### 4. تجربة قصيرة اختيارية

بطاقة صغيرة بعنوان **جرّب الآن** تعرض مثالاً بسيطاً يمكن تعديله وتشغيله. هذه البطاقة تتيح للمستخدم اختبار فكرة التطبيق فوراً، لكنها تأتي بعد إجراء المتابعة الرئيسي ولا تزاحمه.

#### 5. وحدات المسار

اعرض الوحدات بشكل مختصر، مع بيان حالة كل منها:

- مكتملة: علامة نصية أو رمز معتمد.
- الحالية: تمييز واضح وزر للدخول.
- قادمة: عنوانها ظاهر، لكن لا تبدو كأنها مكتملة.

مثال للوحدات الأولى:

1. أول برنامج ومتغيرات.
2. الشروط والقرارات.
3. الحلقات والتكرار.
4. الدوال وإعادة الاستخدام.
5. البيانات والمشروع الأول.

على الهاتف يمكن عرض الوحدات كبطاقات قابلة للتمرير أو قائمة عمودية؛ ينبغي تجنب شريط أفقي صغير لا تظهر فيه أسماء الوحدات كاملة.

#### 6. التنقل الرئيسي

أسماء واضحة مع أيقونة ونص، لا أيقونات منفردة فقط:

- الرئيسية
- المسار
- المشاريع
- الإعدادات

إذا لم تتوفر مشاريع مستقلة في النسخة الأولى، يمكن إظهار مشروع المسار في صفحة المسار بدلاً من عرض وجهة فارغة.

## كيف تختلف الرئيسية بين مستخدم جديد وعائد؟

### المستخدم الجديد

- رسالة ترحيب قصيرة تشرح الفائدة، لا مقدمة طويلة.
- بطاقة رئيسية بعنوان **ابدأ من هنا**.
- زر **ابدأ أول درس**.
- رابط اختياري «أعرف أساسيات البرمجة» لتجاوز مقدمة مناسبة، دون استبيان إلزامي.
- لا تعرض أرقاماً مثل «0% إنجاز» أو تذكيراً بما لم يفعله.

### المستخدم العائد

- زر **تابع التعلّم** يفتح الدرس غير المكتمل مباشرة.
- مؤشر تقدم واضح، مثل «3 من 10 دروس».
- إن كان لديه تمرين غير مكتمل، يمكن الإشارة إليه داخل البطاقة: «بقي تمرين واحد».
- إن لم يوجد درس معلق، اقترح الدرس التالي أو مراجعة قصيرة، مع إبقاء القرار للمستخدم.

## شكل شاشة الدرس

الشاشة تشرح فكرة واحدة ثم تتيح تطبيقها مباشرة. ترتيب مقترح:

```text
[← المسار]                         [1 من 4]

الشروط
اجعل برنامجك يتخذ قراراً باستخدام if.

الفكرة باختصار
إذا تحقق الشرط، ينفذ البرنامج الأوامر التابعة له.

مثال
┌───────────────────────────────────┐
│ var score = 10                    │
│ if score > 0:                     │
│     print("بدأت اللعبة")          │
└───────────────────────────────────┘
[شغّل المثال]

الناتج
بدأت اللعبة

جرّب بنفسك
غيّر الشرط ليظهر النص فقط عندما تكون score أكبر من 5.

┌───────────────────────────────────┐
│ مساحة محرر الشيفرة                │
└───────────────────────────────────┘
[تلميح]                  [شغّل الحل]

رسالة نتيجة / خطأ توضيحية
                         [الدرس التالي ←]
```

### قواعد شاشة الدرس

- اجعل عنوان الدرس وهدفه ظاهرين، مع مؤشر موضع المستخدم في الوحدة.
- افصل شرح الدرس عن منطقة الشيفرة بصرياً.
- أظهر المحرر والناتج في مساحة مريحة، مع تمرير لا يقطع حقل الكتابة.
- اجعل زر التشغيل بارزاً، وزر التلميح ثانوياً.
- عند الخطأ، أظهر رسالة بجانب التمرين أو تحت المحرر، وحدد السطر إن أمكن.
- لا تفتح الحل الكامل تلقائياً؛ ابدأ بتلميح مفيد واترك طلب الحل اختيارياً.
- وفر زر إعادة المثال إلى حالته الأصلية.
- على الهاتف، يظهر الناتج أسفل المحرر؛ وعلى الشاشة العريضة يمكن ترتيب الشرح والمحرر في عمودين.

## قالب صفحة المسار

تظهر الوحدات مرتبة من الأسهل إلى الأكثر تقدماً، وتعرض كل بطاقة اسم الوحدة ووصفاً قصيراً وحالة التقدم. داخل الوحدة، تعرض قائمة الدروس والتمارين التابعة لها، مثلاً:

```text
مسار تعلّم GDScript
تقدّمك: 3 من 10 دروس

✓ 1. أول برنامج
✓ 2. المتغيرات
● 3. الشروط              [تابع]
○ 4. الحلقات             [مقفل حتى إكمال الدرس السابق]
○ 5. الدوال
```

إذا كان قفل الدروس يفرض ترتيباً تعليمياً، فاشرح السبب وأتح خيار استكشاف المحتوى للمستخدم المتقدم إن أمكن. لا تجعل إكمال درس اختيارياً شرطاً قاسياً يمنع الوصول إلى مرجع أو تجربة مستقلة.

## التصميم للشاشات المختلفة

### الهاتف

- ترتيب عمودي وبطاقات بعرض الشاشة.
- زر التشغيل وأزرار الإجراءات كبيرة بما يكفي للمس.
- تجنب عرض الشرح والمحرر في عمودين ضيقين.
- المحرر والناتج قابلان للتمرير بشكل مستقل عند الحاجة، مع بقاء مؤشر الكتابة واضحاً.
- التنقل الرئيسي أسفل الشاشة.

### الجهاز اللوحي أو الحاسوب

- منطقة محتوى بعرض مقروء بدلاً من تمديد النص على كامل الشاشة.
- في الدرس، عمود للشرح وعمود أوسع للمحرر والناتج.
- يمكن وضع المسار في شريط جانبي، مع تثبيت زر المتابعة.
- لا تحوّل مساحة المحرر إلى شريط جانبي ضيق؛ الشيفرة تحتاج عرضاً كافياً.

## أسلوب بصري مقترح

- **الخلفية:** لون محايد فاتح، مع خيار مظهر داكن للمحرر إذا كان مدعوماً.
- **البطاقات:** حدود خفيفة أو تباين بسيط بدلاً من ظلال قوية.
- **اللون الأساسي:** لون واحد للأزرار الرئيسية والتقدم النشط، مع لون ثانوي للنجاح والتحذير والخطأ.
- **الخط العربي:** واضح للقراءة بأحجام مناسبة؛ خط أحادي العرض للشيفرة فقط.
- **الأيقونات:** مساعدة للنصوص وليست بديلاً عن التسميات.
- **الحركة:** انتقالات قصيرة اختيارية، مع دعم تقليل الحركة.
- **الحالات:** النجاح والخطأ والتحذير موضحة بالنص والرمز واللون معاً.

هذه توصيات بداية؛ يمكن اختبار أكثر من لوحة ألوان مع المستخدمين قبل تثبيتها.

## مكونات Flutter المناسبة

اقتراح تقسيم واجهة النسخة الأولى إلى وحدات يسهل اختبارها:

- `HomeScreen`: الترحيب، بطاقة متابعة الدرس، التقدم، والوحدات.
- `LearningPathScreen`: قائمة الوحدات والدروس وحالاتها.
- `LessonScreen`: الشرح والمثال والتمرين والمحرر والناتج.
- `CodeEditor`: إدخال الشيفرة والتلوين والإكمال عند توفرهما.
- `OutputPanel`: ناتج التنفيذ أو رسائل التشخيص.
- `ProgressStore`: قراءة التقدم المحلي وحفظه.

هذه أسماء وظيفية مقترحة وليست التزاماً ببنية ملفات محددة. ينبغي أن تبقى بيانات الدروس والتقدم منفصلة عن بناء الواجهات، وأن تستخدم شاشة الدرس المحرك الداخلي فقط للميزات التي تم التحقق من سلوكها.

## حالات الواجهة التي يجب تصميمها

قبل اعتماد الشاشة الرئيسية والدرس، ينبغي تصور الحالات التالية:

- أول تشغيل، دون تقدم سابق.
- مستخدم يعود إلى درس غير مكتمل.
- مستخدم أكمل جميع الدروس المتاحة.
- الشيفرة قيد التشغيل.
- تشغيل ناجح مع ناتج.
- خطأ نحوي أو تنفيذي مع رسالة قابلة للفهم.
- لا يوجد ناتج مطبوع، مع توضيح أن التنفيذ اكتمل.
- حفظ التقدم أو استعادته بعد إغلاق التطبيق.
- شاشة صغيرة أو لوحة مفاتيح مفتوحة أثناء تحرير الشيفرة.
- حالة فشل الحفظ، مع تنبيه واضح وعدم الإيحاء بأن التقدم حُفظ.

## الخلاصة

الشاشة الرئيسية الناجحة في هذه النسخة لا تحتاج إلى ازدحام أو مزايا اجتماعية. تتكون من ترحيب بسيط، **بطاقة متابعة بارزة**، مؤشر تقدم مفهوم، معاينة للمسار، وتجربة سريعة اختيارية. ثم تنقل المستخدم إلى درس يجمع الشرح القصير والشيفرة والتشغيل والتغذية الراجعة في تدفق واحد. أهم شرط قبل تقديم التجربة على أنها «تعلم GDScript داخل Godot» هو بيان ما يدعمه المحرك الداخلي فعلياً وما لا يدعمه بعد.
