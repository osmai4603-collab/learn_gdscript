# تحذيرات المترجم والتحليل الساكن في GDScript (Compiler Warnings & Static Analysis)

> **المصادر الرسمية:**
>
> - [Godot Docs — Static Typing in GDScript](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/static_typing.html)
> - [Godot Docs — GDScript Warning System](https://docs.godotengine.org/en/stable/tutorials/scripting/gdscript/warning_system.html)
> - [Godot Engine — GDScript Compiler Source & Warnings](https://github.com/godotengine/godot/blob/master/modules/gdscript/gdscript_warning.cpp)

يحتوي محرك Godot 4 على محلل دلالي وتحليلي متقدم (**Static Analyzer**) يفحص كود GDScript أثناء الكتابة وقبل التشغيل لاكتشاف الأخطاء المحتملة، وتنبيه المبرمج للممارسات الخطيرة، وتقديم نصائح لزيادة الأداء وسرعة التنفيذ.

---

## 1. التحديد الصارم للأنواع والفوائد الأدائية (Static Typing)

في GDScript 2.0، لا يقتصر التحديد الصارم للأنواع على تنظيم الكود فقط، بل ينتج عنه تحسينات جوهرية في الأداء:

1. **تسريع التنفيذ المباشر (Direct Bytecode Dispatch)**: عند معرفة نوع المتغير مسبقاً، يستبدل المترجم عمليات البحث الديناميكي عن الميثودات بتعليمات بايت كود مباشرة محسنة بلغة C++، مما يرفع سرعة العمليات الحسابية والحلقات بنسبة تصل إلى **20% - 40%**.
2. **إكمال تلقائي ذكي ودقيق (Autocomplete & LSP)** في المحرر.
3. **اكتشاف الأخطاء مبكراً أثناء التحرير** بدلاً من الانتظار حتى انهيار اللعبة عند التشغيل.

```gdscript
# استنتاج صارم تلقائي باستخدام :=
var speed := 150.0       # المترجم يعرف أنه float
var target_pos := Vector2.ZERO # Vector2

# مصفوفات وقواميس محددة النوع (Typed Collections)
var scores: Array[int] = [10, 20, 30]
var cache: Dictionary[StringName, Variant] = {}
```

## 2. إدارة وتجاوز التحذيرات (`@warning_ignore`)

عندما يطلق المترجم تحذيراً لكود مقصود من المبرمج، يمكن تجاوز التحذير بأحد طريقين:

### أ. على مستوى سطر أو دالة معينة باستخدام المعلمة

```gdscript
# تجاوز تحذير عدم استخدام معامل دالة معينة
@warning_ignore("unused_parameter")
func _process(delta: float) -> void:
    pass

# تجاوز تحذير إهمال القيمة المُرجعة
@warning_ignore("return_value_discarded")
func _ready():
    button.pressed.connect(_on_pressed)
```

### ب. باستخدام البادئة `_` للمتغيرات والمعاملات المهملة

إذا كان لديك متغير أو معامل دالة لا تحتاجه ولكن يجب تعريفه، ضع قبله شرطة سفلية `_` لتخطي تحذير `unused_parameter` أو `unused_variable` تلقائياً دون الحاجة للمعاملة:

```gdscript
# وضع _ قبل delta يتخطى التحذير نظيفاً
func _physics_process(_delta: float) -> void:
    move_and_slide()
```

## 3. الدليل الشامل لأكواد تحذيرات المترجم الرسمية في Godot 4

فيما يلي قائمة بجميع أكواد تحذيرات المترجم المعتمدة رسمياً في Godot 4 مصنفة حسب طبيعتها:

### 1. تحذيرات المتغيرات والموارد غير المستخدمة (Unused Code)

| كود التحذير | سبب التحذير | كيفية الحل |
| :--- | :--- | :--- |
| `unused_variable` | تم تعريف متغير محلي ولم يتم استخدامه في أي عملية. | حذفه أو وضع بادئة `_var_name`. |
| `unused_parameter` | معامل دالة تم تمريره ولكن لم يُستخدم داخل جسم الدالة. | استخدام البادئة `_param` للمعامل. |
| `unused_private_class_variable` | متغير صنف خاص (يبدأ بـ `_`) لم يُستخدم داخل السكربت. | حذفه أو استخدامه. |
| `unused_signal` | تم تعريف إشارة بـ `signal` ولم يتم إطلاقها بـ `.emit()` في أي مكان. | إطلاق الإشارة أو مسحها. |

### 2. تحذيرات أمان الأنواع والتحويلات (Type Safety & Casting)

| كود التحذير | سبب التحذير | كيفية الحل |
| :--- | :--- | :--- |
| `unsafe_property_access` | محاولة قراءة أو كتابة خاصية على كائن غير محدد النوع بدقة (Variant)، مما قد يفشل وقت التشغيل. | استخدام التحديد الصارم للأنواع `as SpecificType`. |
| `unsafe_method_access` | استدعاء دالة على كائن ديناميكي النوع قد لا يحتوي على هذه الدالة. | التحقق بـ `has_method()` أو استخدام `as Type`. |
| `unsafe_cast` | تحويل كائن بنوع عام إلى نوع خاص باستخدام `as` دون التحقق من النتيجة. | التحقق من أن الكائن ليس `null` بعد التحويل. |
| `unsafe_call_argument` | تمرير معامل ذي نوع غير مؤكد لدالة تتطلب نوعاً صارماً. | تحويل المعامل صراحة للنوع المطلوب. |
| `unsafe_void_return` | استدعاء دالة تعيد قيمة داخل دالة نوع إرجاعها `void`. | استدعاء الدالة في سطر منفصل دون `return`. |
| `narrowing_conversion` | تحويل يفقد الدقة، مثل إسناد قيمة `float` لمتغير من نوع `int`. | استخدام دالة تحويل صريحة مثل `int(val)` أو `floor(val)`. |
| `integer_division` | قسمة عدد صحيح على عدد صحيح (مثل `5 / 2`) والتي تنتج عدداً صحيحاً (`2`) متجاهلة الكسور. | تحويل أحد الطرفين لـ float مثل `5.0 / 2`. |
| `int_as_enum_without_cast` | تمرير عدد صحيح عادي `int` لخاصية تنتظر قيمة `enum` محددة. | استخدام اسم التعداد صراحة مثل `MyEnum.VALUE`. |

### 3. تحذيرات حجب الأسماء وتضارب النطاقات (Shadowing)

| كود التحذير | سبب التحذير | كيفية الحل |
| :--- | :--- | :--- |
| `shadowed_variable` | تعريف متغير محلي أو معامل يحمل نفس اسم متغير صنف معرف مسبقاً. | تغيير اسم المتغير المحلي لمنع الالتباس. |
| `shadowed_variable_base_class` | تعريف متغير يحمل نفس اسم خاصية في الصنف الأب الذي ترث منه. | إعادة تسمية الخاصية لتجنب تضارب الوراثة. |
| `shadowed_global_identifier` | تسمية متغير أو دالة بنفس اسم صنف أو دالة عالمية مدمجة (مثل تسمية متغير `var print = 10`). | اختيار اسم مخصص بديل. |

### 4. تحذيرات الأخطاء المنطقية والتدفق (Logic & Flow Hazards)

| كود التحذير | سبب التحذير | كيفية الحل |
| :--- | :--- | :--- |
| `unassigned_variable` | محاولة قراءة قيمة متغير قبل أن يتم إسناد أي قيمة له. | تهيئة المتغير بقيمة افتراضية عند تعريفه. |
| `unassigned_variable_op_assign` | استخدام معامل مركب مثل `+=` على متغير لم يتم تهيئته. | تعيين قيمة ابتدائية للمتغير أولاً. |
| `unreachable_code` | كود مكتوب بعد عبارة `return` أو `break` أو `continue` ولن يُنفذ أبداً. | إزالة الكود الميت الزائد. |
| `unreachable_pattern` | فرع داخل عبارة `match` لن يتم الوصول إليه أبداً لوجود فرع أشمل قبله. | إعادة ترتيب فروع الـ `match` أو حذف الفرع المكرر. |
| `return_value_discarded` | استدعاء دالة تعيد قيمة أو كود خطأ (مثل `connect()` أو `save()`) وتجاهل استقبال قيمتها. | استقبال القيمة بمتغير أو استخدام `@warning_ignore`. |
| `assert_always_true` | كتابة شرط في `assert` محقق دائماً (مثل `assert(true)` أو فحص كائن غير فارغ دائماً). | تصحيح الشرط المراد اختباره. |
| `redundant_await` | استخدام `await` مع دالة أو إشارة لا تحتاج للانتظار لأنها ليست Coroutine. | حذف كلمة `await`. |
| `incompatible_ternary` | العامل الثلاثي `x if cond else y` يعيد نوعين مختلفين تماماً لا يشتركان في نوع واحد. | توحيد نوع النتيجة أو تحديد المتغير كـ `Variant`. |
| `standalone_expression` | سطر يحتوي على تعبير حسابي أو نصي مستقل لا يفعل شيئاً ولا يُسند لمتغير. | إسناد القيمة أو حذف السطر. |
| `standalone_ternary` | استخدام العامل الثلاثي كسطر مستقل بدلاً من جملة `if/else` العادية. | تحويله إلى جملة شرطية عادية `if ...: else: ...`. |

### 5. تحذيرات الممارسات والمحرر (Editor & Architecture Warnings)

| كود التحذير | سبب التحذير | كيفية الحل |
| :--- | :--- | :--- |
| `missing_tool` | السكربت يرث من صنف يحمل المعاملة `@tool` ولكن هذا السكربت يفتقدها. | إضافة `@tool` في أعلى السكربت إذا كان يجب تشغيله بالمحرر. |
| `onready_with_export` | استخدام `@onready` مع `@export` في نفس المتغير (سلوك غير موصى به). | الفصل بين متغير التصدير والتهيئة في الشجرة. |
| `static_called_on_instance` | استدعاء دالة ثابتة `static func` عبر نسخة كائن بدلاً من استدعائها عبر اسم الصنف. | استدعاؤها عبر اسم الصنف مباشرة: `MyClass.my_func()`. |
| `property_used_as_function` | محاولة استدعاء خاصية كدالة (بسبب تشابه الأسماء). | استدعاء الدالة الصحيحة أو إزالة الأقواس. |
| `redundant_static_unload` | استخدام المعاملة `@static_unload` على صنف لا يحتوي على أي متغيرات ثابتة `static var`. | حذف المعاملة. |
| `empty_file` | ملف سكربت فارغ تماماً لا يحتوي على أي كود. | كتابة الكود أو حذف الملف. |
