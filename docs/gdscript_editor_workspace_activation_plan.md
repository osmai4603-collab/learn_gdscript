# الخطة التنفيذية لتفعيل محرر GDScript داخل مساحة العمل

**حالة التنفيذ الحالية:** رُبط `CodeEditorWidget` بمحرر Workspace، مع التلوين
النحوي والدلالي والإكمال ذي البيانات الكاملة، ومساعدة التوقيع ومعلومات hover
المعتمدة على موضع المؤشر، والتشخيصات القابلة للنقر، والتنقل المحلي إلى
التعريف ومطابقة الأقواس، وإدخال الأزواج والمسافة البادئة، والحفظ بـ`Ctrl+S`
وتشغيل النص ومخرجاته. أضيف حفظ selection لكل تبويب. ما زال Outline مؤجلاً
لعدم وجود API رموز موثوق في واجهة المحرك الحالية، والطي الفعلي مؤجلاً لأن
مكوّن `TextField` لا يخفي نطاقات النص؛ كما لا تعرض الواجهة علامات التشخيص
داخل gutter. لا تشمل الحالة formatter آلياً أو debugger أو تشغيل مشروع Godot.

**الهدف:** تفعيل ميزات تحرير GDScript المحددة في
[`gdscript_editor_feature_analysis.md`](./gdscript_editor_feature_analysis.md)
داخل محرر الملفات في Workspace، بترتيب مرحلي واختبارات قبول واضحة.

**النطاق حصراً:** حقل تحرير GDScript المفتوح في مساحة العمل، وتبويبات
المستندات المفتوحة وما يلزمها من حالة تحرير وحفظ، وخدمات المحرر واللوحات
المرتبطة مباشرة بالمستند النشط. لا تتناول هذه الخطة بناء مساحة العمل أو
إعداد جذر المشروع أو مستكشف الملفات أو البحث على مستوى المشروع أو إعادة
الفهرسة.

**مرجعية التنفيذ:** يعتمد التطبيق `gdscript_engine` مباشرةً، ولا تفترض الخطة
وجود LSP. تُراجع واجهات المحرك المستخدمة واختباراتها قبل اعتماد كل ميزة،
وفق [`direct_gdscript_engine_migration_plan.md`](./direct_gdscript_engine_migration_plan.md).

## 1. النطاق الحالي والنتيجة المستهدفة

يحتوي مسار Workspace الحالي على محرر نصوص داخل
`DesktopWorkspaceIdeScreen`، وتملك `WorkspaceScreen` مسودات الملفات
والتبويبات المؤقتة وحفظ ملف GDScript المفتوح عبر `WorkspaceRepository`.
تُحسب تشخيصات الملف النشط من `CodeRunnerService`، لكن منطقة التحرير نفسها
ما زالت `TextField` بسيطاً، ولا تستفيد من ميزات المحرر المتاحة في
`CodeEditorWidget` وخدمات `EditorAPI`.

النتيجة المستهدفة هي محرر GDScript متكامل داخل مساحة العمل، بحيث يعمل
للمستند المفتوح: التلوين، والكتابة الذكية، والإكمال، والتشخيص والتنقل إلى
مواضعها، والتلميحات، والتنقل المحلي، والهيكل والطي حيث يدعمها المحرك،
والتشغيل/المخرجات ضمن حدود `gdscript_engine`. ويجب أن يحافظ المحرر على
استقلال حالة كل تبويب وصحة المسودة والحفظ.

تقتصر الميزات متعددة الملفات في هذا النطاق على **فتح مستندات GDScript
وتبديلها وحفظها**. لا تعني الخطة تحليل جميع ملفات المشروع أو عرض تشخيصات
مشروع كامل أو بحثاً دلالياً عابراً للملفات. يمكن تمرير سياق مشروع محدود
للإكمال إذا ثبتت حاجة API المحرك إليه، لكنه لا يوسع النطاق إلى ميزات إدارة
المشروع.

## 2. ما يدخل وما لا يدخل في الخطة

### داخل النطاق

- محرر النص النشط، اتجاه LTR، الخط، أرقام الأسطر ومزامنة التمرير.
- حفظ حالة المحتوى والمؤشر والتحديد لكل تبويب مفتوح.
- تلوين نحوي ودلالي، وإكمال، ومساعدة توقيع، وhover.
- التشخيصات ذات المواقع والتنقل إليها داخل المستند المفتوح.
- مطابقة الأقواس، التنقل إلى تعريف محلي، Outline وطيّ الكود إذا كانت APIs
  المحرك ومكوّن العرض تدعمها فعلياً.
- حفظ المسودة إلى ملف GDScript المفتوح وإظهار حالة الخطأ/النجاح الصحيحة.
- Console لتشغيل نص GDScript عبر المحرك، إن كان هذا التشغيل مفيداً في
  تجربة المحرر ومطابقاً لسلوك المحرك.
- تحسين اللوحات وعناصر التحكم التي تعرض وظائف المحرر أعلاه فقط.

### خارج النطاق

- إعداد جذر Workspace، اختيار مجلد أو اكتشاف الملفات.
- مستكشف الملفات، طي مجلداته، البحث النصي أو الدلالي على مستوى المشروع،
  وإعادة الفهرسة.
- تحرير وحفظ ملفات المشاهد والموارد، أو تشغيل مشروع/مشهد Godot كاملاً.
- LSP أو خادم لغة أو JSON-RPC.
- تنسيق المستند الآلي إلى أن يعتمد formatter موثوقاً ومختبراً.
- مصحح أخطاء ونقاط توقف وإلغاء التنفيذ، ما لم تتوفر واجهة فعلية لذلك.
- لوحات الطرفية وسجلات الفهرسة وGit وقياسات المحرك/الذاكرة غير المتصلة
  بمصدر بيانات فعلي.

## 3. خريطة ميزات المحرر المستهدف

| الميزة | السلوك المطلوب داخل محرر Workspace | المصدر/الاعتماد |
|---|---|---|
| تحرير متعدد التبويبات | محتوى ومؤشر وتحديد ومسودة مستقلة لكل مستند؛ منع التكرار عند فتح الملف نفسه | حالة المستندات في شاشة Workspace أو طبقة حالة محرر مملوكة لها |
| التلوين | إبراز نحوي ودلالي يتحدث مع النص ولا يغير موضع المؤشر | `getSyntaxHighlights` و`getSemanticHighlights` |
| الكتابة الذكية | Tab/Enter والمسافة البادئة وأزواج الأقواس والاقتباس والتعامل مع التحديد | input formatter قابل للاختبار |
| الإكمال | اقتراحات حسب النص والسياق، تنقل وقبول/إلغاء صحيح | `getCompletions` مع بيانات الاقتراح ونطاق الاستبدال اللازم |
| مساعدة الكتابة | عرض تواقيع الدوال والمعامل النشط وhover عند توفر البيانات | `getSignatureHelp` و`getHoverInfo` |
| التشخيص | عرض الشدة والرسالة والنطاق، تظليل السطر/الهامش، والانتقال للموقع | `getDiagnostics` ونموذج typed يحتفظ بالمواقع |
| التنقل | مطابقة القوس والانتقال إلى تعريف في المستند الحالي | `findMatchingBracket` و`findDefinition` |
| Outline | عرض رموز المستند النشط والتنقل إليها | مصدر رموز مثبت؛ لا يفترض وجود API غير موثق |
| Folding | إخفاء/إظهار نص النطاق فعلياً، لا مجرد تغيير الأيقونة | `getFoldingRanges` مع مكوّن عرض يدعم الطي |
| الحفظ | كتابة المسودة إلى ملف GDScript الحالي، مع بقاء dirty عند الفشل | `WorkspaceRepository.saveGDScriptFile` |
| Console | مخرجات التشغيل والأخطاء الفعلية، إن شُغّل نص المحرر عبر المحرك | `CodeRunnerService.runCode` |
| شريط الحالة | موضع المؤشر وعدد تشخيصات المستند النشط وحالته | قيم حقيقية مرتبطة بالمحرر الحالي |

## 4. مراحل التنفيذ المتسلسلة

### المرحلة 0 — جرد المحرر وتثبيت معايير القبول

**الاعتماد:** لا شيء.

**المهام**

1. حصر ما يعرضه ويتفاعل معه `_WorkspaceEditorPanel`: حقل النص، التبويبات،
   الحفظ، مؤشرات التعديل، أرقام الأسطر، اللوحات، أزرار التشغيل والإعدادات.
2. ربط كل عنصر ذي صلة بالمحرر بميزة من الجدول أعلاه، وتصنيف العناصر الأخرى
   خارج النطاق لإزالتها من واجهة المحرر أو عدم تفعيلها ضمن هذا العمل.
3. مراجعة `CodeEditorWidget` و`CodeRunnerService` وواجهات `EditorAPI`
   المستخدمة فعلياً في محررات التطبيق، وتحديد ما يمكن إعادة استخدامه دون
   إضرار محرر الدروس والتمارين.
4. تعريف سيناريو قبول بمستندين GDScript على الأقل: فتحهما في تبويبين،
   تحرير كل منهما، تبديل التبويب، ظهور ميزات المحرر، ثم حفظ المستند.
5. تسجيل baseline لاختبارات محرر الكود وخدمات المحرك وWorkspace الحالية؛
   تضاف اختبارات محددة قبل أي إعادة استخدام مشتركة.

**بوابة الخروج**

- كل عنصر محرر ظاهر له سلوك حقيقي أو قرار إزالة/تعطيل.
- لا تُخلط وظائف مستكشف المشروع أو البحث العام بميزات محرر المستند.

### المرحلة 1 — تثبيت عقود المحرك ومواضع المؤشر

**يعتمد على:** المرحلة 0.

**المهام**

1. مراجعة عقود APIs التي ستستخدمها الميزات، بما فيها مدخلات النص والمؤشر
   ومخرجات التشخيص والإكمال والتواقيع وhover والتعريف والطي ومطابقة الأقواس.
2. توحيد طريقة تحويل offsets والنطاقات بين Flutter و`gdscript_engine`.
   تثبت وحدة الإحداثيات في عقد المحرك، وتختبر المحارف العربية ومحارف
   Unicode خارج BMP حتى لا ينزاح المؤشر أو نطاق الاستبدال.
3. الاحتفاظ ببيانات الإكمال المتاحة (label، نص الإدراج، النوع، التفاصيل،
   ونطاق الاستبدال) بدلاً من اختزالها إلى `String` إذا كان الاختزال يضر
   بصحة القبول.
4. الاحتفاظ بمعلومات التشخيص اللازمة للواجهة: الشدة والرسالة والمدى والرمز
   الإضافي إن كان متاحاً؛ لا يكفي تمرير قائمة الرسائل النصية.
5. تحديد ملكية المحرك ودورة حياته: تعيد شاشة Workspace استخدام خدمة التطبيق
   المحقونة، ولا تنشئ محركاً لكل تبويب أو تتخلص من محرك لا تملكه.
6. تثبيت ما إذا كان الإكمال يحتاج `CompletionProjectContext`؛ إن احتاجه،
   يمرر سياقاً محدوداً وموثقاً ولا يسمح بقراءة ملفات المشروع ضمنياً.
7. حسم حدود الميزات غير المتاحة: لا يعتمد formatter أو تشخيص متعدد الملفات
   أو تعريف عبر الملفات لمجرد وجود عناصر تصميم تشير إليها.

**الاختبارات**

- عقد لكل API مستخدم مع نص صالح ونص غير مكتمل ونص ذي خطأ نحوي.
- اختبار مواضع بداية/وسط/نهاية النص، واللغة العربية وUnicode.
- اختبار أن الخطأ/النتيجة غير المتاحة لا تتحول إلى اقتراح أو نجاح زائف.

**بوابة الخروج**

- كل API ستستخدمه واجهة المحرر مثبت ومختبر على إصدار الاعتماد الحالي.
- كل موضع أو نطاق له تحويل موحد واختبار يمنع انزياحه.

### المرحلة 2 — مكوّن المحرر وحالة كل مستند

**يعتمد على:** المرحلة 1.

**المهام**

1. استبدال `TextField` الخاص في `_WorkspaceEditorPanel` بمكوّن محرر قابل
   لإعادة الاستخدام، أو تطوير `CodeEditorWidget` ليدعم احتياجات Workspace
   مع الحفاظ على واجهة محرر الدروس والتمارين.
2. إنشاء حالة منفصلة لكل تبويب مفتوح: هوية الملف، النص الحالي، النص
   المحفوظ، حالة dirty، selection/cursor، وأي حالة تمرير تستلزمها تجربة
   التبديل.
3. عند اختيار تبويب، استعادة نصه وموضعه دون إعادة استخدام controller
   يخص مستنداً آخر. فتح الملف نفسه ثانية ينشط تبويبه بدلاً من إنشاء نسخة.
4. ربط تغيير النص بمسودة التبويب النشط وحده، ومنع callback متأخر أو إعادة
   بناء من تعديل مستند غير نشط.
5. عند إغلاق تبويب معدل، تأكيد التخلص من التغييرات. إذا فشل الحفظ، يبقى
   المستند مفتوحاً ومعدلاً؛ ولا يتغير النص المحفوظ المرجعي.
6. تعريف حفظ المستند كجزء من المحرر: لا تعرض حالة «محفوظ» إلا بعد نجاح
   `saveGDScriptFile`، ولا تحفظ أنواع ملفات خارج النطاق.

**الاختبارات**

- التبديل بين مستندين مع نص ومؤشر/تحديد مختلفين.
- إعادة فتح ملف مفتوح تنشط التبويب ذاته.
- تحرير مستند لا يغير dirty أو النص في مستند آخر.
- إغلاق مستند نظيف/معدل، إلغاء التأكيد، فشل الحفظ ونجاحه.

**بوابة الخروج**

- دورة حياة النص والمسودة والحفظ مستقلة وصحيحة لكل تبويب.
- مكوّن المحرر قابل للاستخدام من Workspace دون regression في الشاشات
  التعليمية المعتمدة عليه.

### المرحلة 3 — أساسيات التحرير والتلوين والإدخال الذكي

**يعتمد على:** المرحلة 2.

**المهام**

1. ربط التلوين النحوي والدلالي بالمستند النشط وتحديثه عند تغير النص، مع
   إبقاء النص ومواضع المؤشر والتحديد دون تغيير.
2. ضبط اتجاه النص البرمجي LTR، والخط monospace، والمسافة بين الأسطر،
   وأرقام الأسطر/الهامش بحيث تتطابق مواضعها مع النص.
3. مزامنة تمرير أرقام الأسطر والمحرر واختبار المستند الطويل.
4. تنفيذ Tab وEnter والمسافة البادئة، ثم أزواج الأقواس والاقتباس، والإحاطة
   بالتحديد، وتخطي المحرف الختامي والحذف التلقائي للزوج عند دعم ذلك.
5. إضافة تمييز القوس المطابق من API المحرك، وإزالة التمييز القديم عند
   انتقال المؤشر أو تبديل المستند.
6. التأكد من أن تحديثات تلوين/تنسيق العرض لا تعيد كتابة النص الأساسي ولا
   تفسد undo/redo أو selection.

**الاختبارات**

- الإبراز لا يغير النص أو selection، ويتحدث بعد التعديل والتبديل.
- حالات Enter وTab والأقواس والاقتباس والتحديد والحذف.
- محاذاة أرقام الأسطر وتمريرها مع نص طويل.
- مطابقة الأقواس في مواقع صحيحة وحدودية، وعدم بقاء highlight قديم.

**بوابة الخروج**

- التحرير الأساسي طبيعي وقابل للاستخدام، والتلوين والإدخال يعملان على
  المستند النشط فقط.

### المرحلة 4 — الإكمال والتواقيع وhover

**يعتمد على:** المرحلتين 1 و3.

**المهام**

1. استدعاء الإكمال اعتماداً على نص المستند النشط وموضع المؤشر الصحيح،
   وعرض الاقتراحات قرب المؤشر دون حجب النص أو الخروج عن حدود الشاشة.
2. دعم التنقل بين النتائج بالأسهم، والقبول بلوحة المفاتيح/الفأرة،
   والإلغاء، وCtrl+Space إن كان متوافقاً مع نظام الاختصارات في التطبيق.
3. عند قبول اقتراح، استبدال النطاق الصحيح فقط، وإدارة الأقواس الموجودة
   والمؤشر بعد الإكمال دون تكرار أو فقد محارف مجاورة.
4. ربط `getSignatureHelp` وعرض توقيع الدالة والمعامل النشط عند توفره،
   وتحديثه مع حركة المؤشر أو إدخال المعاملات.
5. ربط `getHoverInfo` بمؤقت قابل للإلغاء، وإغلاق التلميح عند تبديل المستند
   أو تغير النص/الموضع بما يجعل النتيجة قديمة.
6. إظهار حالات لا توجد اقتراحات/معلومات كحالة عادية، وتمرير أخطاء الخدمة
   بطريقة مرئية دون نتائج بديلة توحي بالنجاح.
7. قياس تكلفة طلبات المحرك قبل إضافة debounce أو cache؛ إن أضيفت آلية
   جدولة، يجب إبطال نتائج الطلبات الأقدم والتحقق من هوية المستند.

**الاختبارات**

- قبول إكمال ببداية ووسط ونهاية السطر، مع تحديد نص وقوس تالٍ.
- التنقل والإلغاء وعدم الكتابة فوق نص مجاور.
- تواقيع متعددة المعاملات ومعامل نشط صحيح.
- إلغاء hover المتأخر بعد تغيير المستند أو المؤشر.

**بوابة الخروج**

- لا تُقبل نتيجة إكمال أو تلميح تخص مستنداً أو موضعاً سابقاً.

### المرحلة 5 — التشخيص والتنقل وOutline والطي

**يعتمد على:** المرحلتين 1 و3؛ وتتكامل الإكمالات مع نتائج هذه المرحلة عند الحاجة.

**المهام**

1. حساب تشخيصات المستند النشط فقط. لا تعرضها على أنها تشخيصات Workspace
   كاملة، ولا تحلل جميع الملفات ضمن هذه الخطة.
2. تحويل نتائج المحرك إلى نموذج يحفظ الشدة والمدى؛ استخدامه لعلامات
   الهامش وتظليل السطر وProblems panel والتلميح.
3. اختيار التشخيص ينقل المؤشر والتمرير إلى موضعه داخل المستند الحالي.
   يمنع اعتماد تشخيص قديم بعد تعديل النص أو تبديل التبويب.
4. ربط التنقل إلى تعريف داخل المستند الحالي عندما يعيد المحرك موضعاً صالحاً؛
   لا تعرضه كبحث تعريف على مستوى المشروع.
5. إضافة Outline للمستند النشط فقط بعد تثبيت مصدر الرموز. إذا لم يوفر
   المحرك استخراجاً موثوقاً، يؤجل العنصر بدلاً من إخفاء خطأ التحليل أو
   إنشاء parser موازٍ غير مختبر.
6. ربط Folding ranges بإخفاء النص فعلياً. إذا لم يدعم مكوّن المحرر ذلك
   بأمان، يؤجل الطي وتزال/تعطل أيقونته؛ لا تكتف بتغيير حالة شكلية.
7. ربط مطابقة الأقواس والرموز النشطة/شريط الحالة بمواضع حقيقية من المستند.

**الاختبارات**

- تشخيص من كل شدة مع مدى صالح، واختيار المشكلة ينقل إلى الموقع الصحيح.
- لا تبقى تشخيصات أو رموز من تبويب سابق.
- تعريف محلي موجود/غير موجود، وOutline لنص صالح وغير مكتمل.
- طي/فتح النطاق يحفظ النص كاملاً ولا يفسد offsets أو الحفظ.

**بوابة الخروج**

- كل تشخيص وتنقل مرتبط بالمستند الحالي وموقع مثبت، وكل ميزة غير مدعومة
  مستبعدة بوضوح.

### المرحلة 6 — Console وتشغيل الشيفرة وحالة المحرر

**يعتمد على:** المرحلة 5.

**المهام**

1. إضافة/استكمال لوحة Console للمحرر فقط، وربطها بمخرجات
   `CodeRunnerService.runCode` الفعلية، مع الأخطاء وزمن التنفيذ وعدد
   التعليمات عندما يعيدها المحرك.
2. تحديد دلالة التشغيل بوضوح: تشغيل نص GDScript عبر المحرك لا يشغل
   مشروع Godot أو مشهداً. تسمية الزر والنتيجة بما لا يوحي بخلاف ذلك.
3. إظهار حالة التشغيل والنتيجة المرتبطة بطلب التشغيل الحالي، ومنع مخرجات
   طلب سابق من الظهور على أنها نتيجة المستند/التشغيل الأحدث.
4. عدم إظهار زر إيقاف فعال إذا لم يدعم المحرك الإلغاء الحقيقي؛ لا يُكتفى
   بتبديل مؤشر التشغيل.
5. توفير مسح Console وإظهار/إخفاء اللوحة عند الحاجة، وإزالة التبويبات أو
   السجلات غير المرتبطة بميزات محرر ضمن النطاق.
6. ربط شريط الحالة بموضع السطر/العمود وعدد تشخيصات الملف وحالة الحفظ
   الفعلية؛ عدم استخدام أرقام أو حالات ثابتة.

**الاختبارات**

- تشغيل ناجح وفاشل وعرض المخرجات والخطأ الفعليين.
- تبديل التبويب أثناء التشغيل لا ينسب النتيجة إلى المستند الخطأ.
- زر الإيقاف غير فعال/غير ظاهر إن لم تتوفر قابلية الإلغاء.
- مسح اللوحة والحالات الفارغة لا تعرض بيانات تجريبية.

**بوابة الخروج**

- كل ما في Console وشريط الحالة صادر عن المستند/المحرك فعلياً، والتشغيل
  لا يوصف بأنه تشغيل مشروع Godot.

### المرحلة 7 — التعريب والاستجابة والتحقق النهائي

**يعتمد على:** المراحل السابقة.

**المهام**

1. إضافة تسميات ورسائل ميزات المحرر الجديدة إلى ARB وتوليد ملفات الترجمة
   بالطريقة المعتمدة في المشروع.
2. ضبط تخطيط المحرر والـoverlays واللوحات على سطح المكتب والعرض الضيق؛
   الحفاظ على LTR للشيفرة وعدم حدوث overflow أو حجب أدوات التحرير.
3. اختبار الوصول بلوحة المفاتيح، focus، الاختصارات، أدوات التلميح،
   والرسائل المرئية لحالات الخطأ والفراغ والحفظ.
4. تشغيل التنسيق والتحليل الساكن واختبارات خدمة المحرك ومكونات المحرر
   واختبارات Workspace الموجهة، ثم المجموعة الكاملة عند نجاح الموجهة.
5. تنفيذ اختبار قبول يدوي داخل Workspace: فتح ملفين موجودين، تحرير كل
   منهما، استخدام التلوين والإكمال والتشخيص/التنقل المدعوم، التبديل،
   الحفظ وإعادة فتح المستند للتحقق من بقاء المحتوى.
6. قياس زمن التلوين والتشخيص والإكمال على مستند واقعي؛ أي debounce/cache
   إضافي يجب أن يستند إلى قياس واختبارات إبطال.
7. تحديث وثائق المحرر لتسجيل الميزات التي اكتملت وما بقي خارج النطاق؛
   لا تعدل تدفق إعداد Workspace أو البحث العام كجزء من هذه المرحلة.

**بوابة الإطلاق**

- تنجح اختبارات المحرر والبناء المستهدف، أو توثق عوائق البيئة بوضوح.
- لكل ميزة معروضة اختبار قبول؛ لا توجد أزرار شكلية أو بيانات عينة أو
  نجاح/حفظ زائف.

## 5. ترتيب الاعتماد

```text
0 جرد محرر Workspace ومعايير القبول
  → 1 عقود EditorAPI ومواضع النص
  → 2 مكوّن المحرر وحالة كل مستند
  → 3 أساسيات التحرير والتلوين والإدخال الذكي
  → 4 الإكمال والتواقيع وhover
  → 5 التشخيص والتنقل وOutline والطي
  → 6 Console وتشغيل الشيفرة وشريط الحالة
  → 7 التعريب والاستجابة والاختبارات والإطلاق
```

لا يبدأ توصيل ميزات المحرك قبل تثبيت عقدها في المرحلة 1، ولا يبدأ تطوير
Outline أو Folding قبل إثبات مصدر الرموز وقدرة مكوّن العرض على إخفاء النص.
يمكن إخراج الميزات المعتمدة تباعاً؛ لا يلزم انتظار ميزات مؤجلة مثل formatter
أو debug لتفعيل التلوين والإكمال والتشخيص.

## 6. المخاطر وضوابطها

| الخطر | الأثر | الضابط |
|---|---|---|
| اختلاف وحدة offsets أو Unicode | تحريك المؤشر/التشخيص إلى موضع خاطئ | اختبار UTF-16 والعربية ومحارف Unicode ومقارنة round-trip |
| استجابة تحليل قديمة | نتائج لمحتوى أو تبويب سابق | هوية للمستند ورقم تسلسلي لكل طلب قبل تطبيق النتيجة |
| إعادة استخدام المحرر تكسر الدروس | تراجع تجربة الدروس والتمارين | اختبارات regression للمكونات المشتركة قبل وبعد التغيير |
| اختلاط controller أو dirty بين تبويبين | حفظ النص الخطأ أو فقد مسودة | حالة مستقلة لكل مستند واختبارات التبديل والحفظ والفشل |
| بطء المحرك أثناء الكتابة | تقطع تجربة التحرير | قياس الأداء أولاً، ثم تحسين/جدولة بأقل تعقيد لازم |
| ادعاء ميزات غير موجودة | واجهة مضللة ونتائج غير موثوقة | استبعاد التنسيق وdebug والتحليل الشامل ما لم يثبت API وخدمة واختبار |
| الخلط بين تشغيل النص وتشغيل Godot | توقعات مستخدم خاطئة | تسمية واضحة وحدود تشغيل ظاهرة في الواجهة والتوثيق |

## 7. المخرجات النهائية

- محرر GDScript فعلي داخل Workspace، بمكوّن موحد قدر الإمكان مع بقية
  محررات التطبيق.
- حالة مستقلة وصحيحة للمحتوى والمؤشر والتحديد والحفظ لكل تبويب مفتوح.
- ميزات `EditorAPI` المعتمدة موصولة بواجهة واختبارات من طرف إلى طرف.
- تشخيصات وOutline وFolding وConsole لا تعرض إلا بيانات حقيقية ومحدودة
  بالمستند الذي تعمل عليه.
- توثيق واضح للميزات المؤجلة، وبالأخص التنسيق الآلي والتصحيح وتشغيل مشروع
  Godot والتحليل الدلالي عبر الملفات.
