# الخطة التنفيذية للمرحلة الخامسة: الميزات المتقدمة

تعتمد هذه الخطة على المرحلة الخامسة في [الخطة التنفيذية الشاملة](./execution_plan.md)، وتحوّل نطاقها إلى مهام قابلة للتنفيذ والتحقق. تركز على استكمال الميزات المتقدمة ودمجها مع بنية التطبيق الحالية، لا إعادة بناء ما أُنجز.

## الهدف والنطاق

إضافة أدوات تعزز التعلم بعد توفر الواجهات والمحتوى ونظام التقدم:

1. مستكشف الصياغة.
2. البحث النصي والرمزي في مساحة العمل.
3. المراجعة المتباعدة وحفظ مواعيدها.
4. خريطة مفاهيم مرتبطة بالمنهج والتقدم.
5. مشروع تطبيقي تدريجي: لعبة تخمين الرقم.
6. دعم أنواع التمارين الإضافية والتحقق من تكاملها.

**المدة التقديرية للمرحلة كاملة:** 10-14 يوم عمل.  
**المدة المتبقية التقديرية وفق مراجعة الشيفرة الحالية:** 7-11 يوم عمل، وتتغير بعد حسم تفاصيل المحرك وتجربة البحث والتنقل.  
**الاعتماديات:** المرحلة 3 (الواجهات وLSP) والمرحلة 4 (التقدم والتحفيز).

## الوضع الحالي ونقطة البداية

هذه لقطة تنفيذية عند إعداد الخطة؛ تُحدّث الحالات أثناء التنفيذ:

| المجال | الموجود في المشروع | ما يزال مطلوباً |
| :--- | :--- | :--- |
| مستكشف الصياغة | شاشة مرجع الصياغة ومستودع وملفات بيانات موجودة تحت `lib/ui/screens/syntax_reference/` و`assets/syntax_reference/`. عدّاد استخدامه مرتبط بالتقدم. | استكمال الفلاتر والبحث التفاعلي وزر تجربة المثال وربط التنقل إلى الدرس ذي الصلة، والتحقق من اكتمال البيانات المعروضة. |
| بحث مساحة العمل | شاشة وأوامر بحث نصي ورمزي متصلة بعميل LSP وفهرسة مساحة العمل. | عرض نتائج منظمة قابلة للتنقل في المحرر، وتوضيح جاهزية الفهرسة وحالاتها وأخطائها قبل البحث، واختبار المواضع عبر ملفات متعددة. |
| أنواع التمارين | `fixBug` و`reorderSteps` معرفان في النماذج، وموجودان ضمن بيانات المنهج واختبارات المحتوى. | التحقق من تدفق الإجابة والتقييم والتغذية الراجعة وحفظ التقدم لكل نوع، وإضافة تغطية اختبارية للفجوات فقط. |
| المراجعة المتباعدة | أضيفت خدمة حساب جدولة أولية وشاشة عرض أولية تحت `lib/logic/services/review_service.dart` و`lib/ui/screens/review/`. | استكمال نموذج المراجعة، التخزين الدائم، إنشاء العناصر، تدفق السؤال والإجابة، والربط بالتقدم. |
| خريطة المفاهيم | أضيفت شاشة أولية تحت `lib/ui/screens/concept_map/` بعقد ثابتة تجريبية. | توليد العقد من المنهج، ربط حالتها بالتقدم الفعلي، وتحويل العرض إلى خريطة تفاعلية. |
| المشروع التطبيقي | أضيفت شاشة أولية تحت `lib/ui/screens/capstone/` بقائمة مراحل غير محفوظة. | إضافة محتوى ومحرر وتحقق لكل مرحلة، قفل المراحل حسب المتطلبات، وحفظ التقدم والكود. |

المسارات المذكورة تصف الموجود حالياً لتسهيل الاستكشاف؛ يجب إعادة التحقق منها قبل كل تغيير، والمحافظة على أي تعديلات أحدث في الشيفرة.

## مبادئ التنفيذ

- إعادة استخدام نماذج المحتوى والتقدم ومستودعات التطبيق وموفرات الحالة الموجودة قبل إضافة أي بنية جديدة.
- اعتماد ملفات البيانات الفعلية وعقود LSP الحالية؛ لا تُنسخ بيانات مرجع الصياغة أو فهرسة مساحة العمل إلى مصدر ثانٍ.
- حفظ أي حالة يتوقع استمرارها بعد إغلاق التطبيق في قاعدة البيانات المحلية، مع ترحيل متوافق واختبار استعادة البيانات.
- دعم العربية والإنجليزية واتجاهي RTL/LTR، والمحافظة على عرض الشيفرة LTR، ومراعاة المظهرين الفاتح والداكن.
- إظهار حالات التحميل والفراغ والأخطاء بوضوح، وعدم تقديم استجابة شكلها نجاح عند تعذر LSP أو التخزين.
- تقسيم العمل إلى تغييرات صغيرة، وإضافة اختبارات الوحدة والودجت والتكامل لكل ميزة بحسب حدودها.

## ترتيب التنفيذ والمهام

## قائمة مهام قابلة للتنفيذ والتتبع

تجزّئ هذه القائمة الأعمال المتبقية إلى وحدات يمكن إنجاز كل منها والتحقق منها مستقلاً. علامة `[ ]` تعني أن المهمة غير مكتملة؛ وجود شاشة أو نموذج أولي لا يُعد إنجازاً للميزة قبل استيفاء شرط قبولها.

### أ. خط الأساس والتكامل

- [ ] **A1 — تثبيت خط الأساس:** تشغيل اختبارات المحتوى وLSP والتقدم والتمارين وتسجيل أي إخفاق سابق.
- [ ] **A2 — التحقق من عقود التنقل وLSP:** توثيق كيفية فتح ملف عند موضع محدد، وحالة جاهزية الفهرسة، والنتائج التي يعيدها الخادم.
- [ ] **A3 — ربط الميزات بالتطبيق:** التأكد من وجود مسارات دخول ظاهرة للمراجعة والخريطة والمشروع، لا مجرد تعريف مساراتها في التوجيه.

### ب. مستكشف الصياغة

- [ ] **B1 — فلاتر المرجع:** إضافة فلاتر الكل والكلمات المفتاحية والدوال المدمجة والأنواع اعتماداً على تصنيف البيانات.
- [ ] **B2 — بحث مباشر وحالاته:** تحديث النتائج عند الكتابة أو تغيير الفئة، وإظهار التحميل والنتائج الفارغة والأخطاء.
- [ ] **B3 — تفاصيل وتجربة المثال:** عرض الشرح والصياغة والمثال، وربط زر التجربة بخدمة التشغيل أو توضيح عدم توفر التشغيل.
- [ ] **B4 — الربط بالدرس والاختبارات:** إتاحة فتح الدرس المرتبط واختبار الفلاتر واللغتين والروابط واحتساب الاستخدام.

### ج. بحث مساحة العمل

- [ ] **C1 — شرط جاهزية البحث:** منع البحث دون مساحة عمل وفهرسة جاهزة، وعرض التقدم أو الخطأ للمستخدم.
- [ ] **C2 — بطاقات النتائج المنظمة:** تحويل استجابات LSP النصية والرمزية إلى نتائج مقروءة تتضمن الملف والسطر والمقتطف المتاح.
- [ ] **C3 — فتح النتيجة في المحرر:** تمرير URI والموضع، وفتح الملف أو المستند والانتقال للموقع الصحيح.
- [ ] **C4 — تغطية سيناريوهات LSP:** اختبار البحث عبر ملفات متعددة، وانقطاع الخادم، والفهرسة غير المكتملة، والنتائج الفارغة.

### د. المراجعة المتباعدة

- [ ] **D1 — نموذج وقرار الجدولة:** تحديد نموذج عنصر المراجعة وقاعدة الفواصل واختبارها بوقت محقون.
- [ ] **D2 — التخزين والترحيل:** حفظ العناصر والنتائج والمواعيد لكل مستخدم، مع اختبار الاستعادة بعد إعادة فتح قاعدة البيانات.
- [ ] **D3 — إنشاء المراجعات المستحقة:** إنشاء/تحديث عنصر دون تكرار بعد إكمال تمرين أو درس مناسب.
- [ ] **D4 — تدفق سؤال وإجابة:** عرض سؤال فعلي، تقييم الإجابة، إظهار التفسير، وتحديث موعد المراجعة للصحيح والخاطئ.
- [ ] **D5 — ربط الشاشة واختبارها:** إزالة البيانات التجريبية من الشاشة وربطها بالمستودع والموفر وحالات التحميل والفراغ والخطأ.

### هـ. خريطة المفاهيم

- [ ] **E1 — بيانات الخريطة:** إنشاء نموذج أو مصدر بيانات للعقد والروابط مربوط بمعرفات المنهج والدروس.
- [ ] **E2 — حالة التقدم:** اشتقاق المكتمل والحالي والمقفل من تقدم المستخدم وقواعد فتح الدروس، وإزالة الحالات الثابتة التجريبية.
- [ ] **E3 — تفاعل الخريطة:** دعم الاستكشاف/التكبير والتنقل بين العقد، مع فتح الدرس الصحيح وإظهار ملخص المفهوم.
- [ ] **E4 — اختبار التوافق:** اختبار اتساق البيانات مع المنهج، وحالة التقدم والتنقل والتجاوب مع شاشة ضيقة.

### و. المشروع التطبيقي

- [ ] **F1 — محتوى المراحل الست:** تعريف الهدف والكود الابتدائي والتلميحات والاختبار لكل مرحلة باللغتين.
- [ ] **F2 — التحقق من المحرك:** إثبات دعم توليد الرقم العشوائي في المحرك المستهدف واختيار الصيغة المتوافقة.
- [ ] **F3 — فتح المراحل وتسلسلها:** قفل المشروع حتى استيفاء الشرط، وعدم فتح مرحلة قبل نجاح السابقة.
- [ ] **F4 — محرر وتقييم المرحلة:** تمكين المستخدم من كتابة الكود وتشغيل اختبارات المرحلة وإظهار أسباب النجاح أو الفشل.
- [ ] **F5 — حفظ واستعادة المشروع:** تخزين الكود والمرحلة الحالية والإنجازات، واختبار استعادتها بعد إعادة التشغيل.
- [ ] **F6 — اختبار رحلة المشروع:** تغطية القفل، التقدم، إعادة المحاولة، وعدم فقدان المراحل المكتملة.

### ز. أنواع التمارين والإغلاق

- [ ] **G1 — تتبع `fixBug`:** اختبار تحميله وعرضه وتحريره وتقييمه وتلميحاته وتسجيل تقدمه.
- [ ] **G2 — تتبع `reorderSteps`:** اختبار السحب والترتيب والإجابة الصحيحة والخاطئة والتغذية الراجعة وتسجيل التقدم.
- [ ] **G3 — التكامل وإمكانية الوصول:** مراجعة المسارات والترجمة وRTL/LTR والمظهرين وحالات الأخطاء لكل الميزات.
- [ ] **G4 — التحقق النهائي:** تشغيل الاختبارات المستهدفة ثم `flutter analyze` و`flutter test` وتسجيل النتائج قبل إعلان الاكتمال.

**قاعدة التنفيذ:** ابدأ بـA1 وA2، ثم نفذ B وC وD وE بالتوازي عند توفر أصحاب العمل؛ ابدأ F1 بالتوازي، لكن لا تعتمد F3-F5 على بيانات مؤقتة. نفذ G1-G4 بعد استقرار الميزات ذات الصلة. لا تُعلّم أي بند منجزاً إلا مع اختبار قبول يثبت السلوك.

### 0. تثبيت خط الأساس والتحقق من الجاهزية

**المدة:** نصف يوم  
**الحالة:** مطلوب قبل التنفيذ

- مراجعة التوجيه، موفرات الحالة، إدارة المحرر، مستودع المحتوى والترحيلات الحالية.
- تشغيل اختبارات المحتوى وLSP والتقدم والتمارين ذات الصلة وتسجيل النتائج الأساسية.
- تحديد واجهة فتح الملف عند موضع محدد وإمكانية عرض حالة الفهرسة من موفر LSP الحالي.
- اعتماد قائمة الفجوات الفعلية لكل بند في جدول الوضع الحالي.

**المخرجات:** قائمة فجوات مؤكدة ومسارات تكامل متفق عليها، دون تعديل السلوك القائم.

### 1. استكمال مستكشف الصياغة

**المدة:** يوم إلى يومين  
**الحالة:** قائم جزئياً  
**يعتمد على:** المهمة 0

- إضافة مرشحات «الكل» و«الكلمات المفتاحية» و«الدوال المدمجة» و«الأنواع»، بالاعتماد على تصنيف بيانات المستودع.
- جعل البحث والمرشحات يعكسان النتائج بوضوح عند تغيير النص أو الفئة، مع حالة فارغة عند عدم وجود نتائج.
- عرض عنوان العنصر وصيغته وشرحه ومثاله، وتوفير زر لتجربة المثال عبر خدمة تشغيل الكود الموجودة إن كان سياق التشغيل يدعمه؛ وإلا توضيح القيد للمستخدم.
- إتاحة الانتقال إلى الدرس ذي الصلة عند توفر معرف درس صالح.
- المحافظة على احتساب استخدام المستكشف وفق السلوك الحالي، ومنع احتساب البحث الفاشل أو التفاعلات المتكررة غير المقصودة على نحو مضلل.

**الاختبارات:** تصفية حسب الفئة، بحث بلا نتائج، عرض اللغتين، ارتباط الدرس، وتشغيل المثال أو إظهار حالة التعذر.

### 2. استكمال بحث مساحة العمل والتنقل إلى النتائج

**المدة:** يومان إلى ثلاثة أيام  
**الحالة:** قائم جزئياً  
**يعتمد على:** المهمة 0؛ يمكن تنفيذه بالتوازي مع المهمة 1 بعد تثبيت العقود

- تعطيل البحث ما لم توجد مساحة عمل محددة وفهرسة مكتملة وحديثة، مع إظهار الحالة والتقدم وأخطاء الفهرسة أو القراءة.
- عرض النتائج النصية والرمزية كمكونات منظمة، تشمل المسار والسطر والمقتطف والسياق المتاح، بدلاً من عرض استجابة JSON الخام.
- فتح نتيجة الرمز أو النص في المحرر عند الملف والموضع الصحيحين، مع التحقق من أن المستند ما زال مفهرساً وحديثاً.
- توضيح حالات لا توجد نتائج، وانقطاع الخادم، والنتائج القديمة أو فشل الانتقال.
- التأكد أن البحث عبر عدة ملفات يستخدم فهرس التطبيق المرسل إلى خادم LSP، دون افتراض فهرسة تلقائية من الخادم.

**الاختبارات:** بحث نصي ورمزي عبر ملفين على الأقل، نتيجة فارغة، خادم غير متصل، فهرسة غير مكتملة، وفتح نتيجة عند موضعها.

### 3. بناء المراجعة المتباعدة

**المدة:** يومان إلى ثلاثة أيام  
**الحالة:** غير منفذة  
**يعتمد على:** المهمة 0

- تعريف نموذج مراجعة يحدد المفهوم أو التمرين ومصدره، موعد المراجعة، الفاصل الحالي، وعدد الإجابات الصحيحة المتتالية أو حالة الإتقان اللازمة للجدولة.
- تحديد قاعدة جدولة بسيطة وثابتة قبل التنفيذ: الإجابة الصحيحة تزيد الفاصل تدريجياً، والخاطئة تعيد العنصر في اليوم التالي. تثبيت حدود الفواصل والتقريب باختبارات حتمية.
- إنشاء/تحديث عناصر المراجعة من التمارين التي أكملها المستخدم، مع منع التكرار لنفس المستخدم والعنصر.
- إضافة تخزين محلي وترحيل قاعدة بيانات عند الحاجة، مع حفظ نتيجة كل مراجعة وموعدها التالي واستعادتها بعد إعادة التشغيل.
- توفير خدمة لجلب العناصر المستحقة في تاريخ محدد، لا الاعتماد على الساعة الحقيقية داخل الاختبارات.
- إضافة شاشة أو قسم «مراجعة اليوم» يعرض عدد العناصر المستحقة، السؤال، إجابة المستخدم، النتيجة، والتفسير؛ مع حالات التحميل والفراغ والخطأ.
- استخدام أنواع الأسئلة المدعومة: توقع الناتج، ملء الفراغ، وإصلاح الخطأ، مع الاستفادة من عارض التمرين وخدمة التقييم الحاليين.

**الاختبارات:** الجدولة للصحيح والخاطئ، حدود الفاصل، منع التكرار، عناصر مستحقة/غير مستحقة، ترحيل واستعادة البيانات، وتدفق واجهة سؤال واحد على الأقل لكل نوع مستخدم.

### 4. تنفيذ خريطة المفاهيم

**المدة:** يوم إلى يومين  
**الحالة:** غير منفذة  
**يعتمد على:** المهمة 0؛ يستفيد من معرفات الوحدات والدروس والتقدم الحالية

- بناء بيانات العقد والروابط من المنهج الحالي، مع معرف ثابت لكل مفهوم وروابط صريحة بالدروس ذات الصلة.
- عرض الخريطة ضمن مساحة قابلة للتحريك والتكبير والتصغير، ببديل مناسب للأحجام الصغيرة أو عند تعذر التخطيط البصري.
- تمييز المفاهيم المكتملة والحالية وغير المفتوحة اعتماداً على تقدم المستخدم الفعلي، لا على حالة تجريبية ثابتة.
- عرض ملخص محلي للعقدة، وإتاحة فتح الدرس المرتبط بها وفق قواعد فتح الدروس الحالية.
- توفير دعم لوحة المفاتيح/التركيز والعناصر الدلالية الأساسية، وعدم جعل اللون وحده مؤشراً للحالة.

**الاختبارات:** اتساق العقد والروابط مع المنهج، انعكاس حالات التقدم، فتح الدرس الصحيح، وتجاوب الواجهة مع شاشات ضيقة.

### 5. إضافة المشروع التطبيقي التدريجي

**المدة:** يومان إلى ثلاثة أيام  
**الحالة:** غير منفذة  
**يعتمد على:** المهام 0 و3؛ ويمكن إعداد المحتوى بالتوازي مع المهمة 4

- نمذجة المشروع كست مراحل مستقلة ذات معرفات ثابتة ومتطلبات سابقة واضحة.
- توفير وصف عربي وإنجليزي لكل مرحلة، كود بداية، هدف قابل للتحقق، تلميحات متدرجة، واختبار أو معايير نجاح.
- ترتيب المراحل كالتالي: رسالة ترحيب، توليد رقم عشوائي، مقارنة التخمين، التكرار حتى النجاح، تنظيم المنطق بدالة، ثم عداد المحاولات والنتيجة النهائية.
- التحقق من دعم المحرك الفعلي للدوال العشوائية المقترحة قبل اعتمادها؛ استخدام بديل موثق أو تعديل الخطوة إذا لم تكن مدعومة.

- فتح المشروع بعد استيفاء شرط الإكمال المتفق عليه للوحدات الخمس، مع إظهار سبب القفل للمستخدم.
- عرض تقدم إجمالي وخيارات متابعة أو إعادة المحاولة، دون إعادة ضبط إنجاز سابق عند الفشل في اختبار مرحلة.

**الاختبارات:** قفل المشروع وفتحه، تقدم المراحل بالترتيب، رفض تخطي المتطلبات، نجاح وفشل التحقق، حفظ الكود والتقدم واستعادتهما، وتوافق المحتوى والاختبارات مع المحرك.

### 6. إغلاق فجوات أنواع التمارين واختبارها طرفاً إلى طرف

**المدة:** نصف يوم إلى يوم  
**الحالة:** دعم النماذج والمحتوى موجود؛ التكامل يحتاج تحققاً  
**يعتمد على:** المهمة 0، ويُنفذ بعد المهام التي تستعمل أنواع التمارين

**الاختبارات:** اختبارات ودجت للإجابات الصحيحة والخاطئة، اختبار تدفق محتوى حقيقي لكل نوع، وتحقق من حفظ التقدم وعدم احتساب الإكمال مرتين.

### 7. التكامل والتحقق النهائي
